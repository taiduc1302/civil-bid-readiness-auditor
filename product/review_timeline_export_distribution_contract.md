# Review Timeline export browser distribution contract

## Scope

This contract governs the local browser **download** surface for the already-defined `civil-estimate-review-timeline-export` v1 format. It does not change the export format, canonical evidence model, integrity contract, or independent verifier.

The only browser distribution route in this increment is:

- `GET /export-review-timeline` — render the local request form;
- `POST /export-review-timeline` — accept freshly selected Delta v1 ZIPs, build one Timeline export, independently verify the generated export, and return it as `application/zip` only if every gate succeeds.

There is no Timeline-export ZIP upload/ingestion/continuation/restoration route in this increment.

## Fresh-input trust boundary

The browser route accepts only the existing `delta_export` multipart fields. The user must re-select **2–10** Review Delta v1 ZIPs for that request.

The route must not accept, copy, infer, or carry from `/review-timeline` or another route:

- uploaded ZIP bytes;
- a verifier result or `verified=true` flag;
- bounded Timeline preview rows;
- package identity or lineage state;
- a review session token;
- hidden evidence fields; or
- browser persistence used as evidence authority.

Each request reuses the dedicated Review Timeline multipart parser and therefore keeps the existing per-Delta and aggregate request bounds. The export core then independently verifies every Delta and reconstructs the one connected acyclic review-package SHA-256 chain from scratch.

## Pre-distribution gate

The generated ZIP is not written to the HTTP response merely because the builder returned bytes.

Before distribution, the route must call `verify_review_timeline_export()` on the exact generated bytes and require:

- `valid=true`; and
- `heavybid_import_validated=false`.

Any parsing, Delta verification, lineage, export-construction, output-bound, integrity, semantic, deterministic-regeneration, or pre-distribution verification failure returns an HTML `400 Bad Request` response and no ZIP bytes.

## Response contract

On success the route returns:

- HTTP `200`;
- `Content-Type: application/zip`;
- a deterministic Timeline-export filename from the builder;
- exact `Content-Length`; and
- the exact independently verified export bytes.

The request creates no `SESSIONS` entry and writes no application persistence.

## Safety boundary

The browser distribution surface does not:

- restore source files;
- create or continue a review session;
- rerun estimate audit rules or governed references;
- infer calendar chronology, elapsed time, source currency, revision rank, quality, improvement/regression, approval, or bid readiness;
- generate a narrative, recommendation, trend, or score;
- reconstruct or port Operational Crew Code / Production Rate evidence;
- create controlled-output eligibility;
- write to HeavyBid or perform a HeavyBid import; or
- invent Bid Item, Activity, Resource, Crew, Production, Rate, or Quantity values.

`HEAVYBID_IMPORT_VALIDATED=false` remains immutable.

## Explicit non-goals

- no browser verification/upload screen for an already-created Timeline export in this increment;
- no archived continuation or restoration from Timeline export evidence;
- no persistent timeline/history store;
- no cross-route evidence handoff;
- no automatic source-currentness or commercial revision inference; and
- no HeavyBid candidate writer/import behavior.
