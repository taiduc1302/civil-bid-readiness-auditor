# User workflow

1. Start the local server and open the displayed `http://127.0.0.1` URL. New users can open the fictional onboarding walkthrough from the home page.
2. For the basic walkthrough, run the normal synthetic sample. For hierarchy/reference practice, the guide can **Run structured fictional sample**, which loads only the bundled `synthetic_heavybid_style_resource_export.csv` into the normal editable mapping flow.
3. The guide also provides direct downloads for the bundled fictional Activity/Resource reference CSVs. These files are fictional and are never auto-applied; upload them manually only after auditing the structured demo.
4. For normal work, upload a CSV or XLSX estimate export and review detected worksheets and column mapping. Required fields are Description, Quantity, Unit, and Rate. Optional hierarchy fields include Bid Item, Activity, Resource Type, and Resource Code.
5. If a supported HeavyBid-style flat resource export is recognized, review the exact-alias preselected mappings. Recognition is fail-closed and all mappings remain editable.
6. Run the deterministic audit.
7. Use the review attention summary and stable temporary findings view to identify Open / Needs correction attention items, then filter, sort, group, or search findings. These controls never change deterministic findings or saved review state.
8. Inspect sheet/row evidence and record a temporary human disposition for each finding: `Open`, `Reviewed`, `Accepted`, `Needs correction`, or `Suppressed`. Suppressed findings require a reason. Dispositions do not alter the estimate, deterministic finding, severity, or legacy score.
9. For multiple findings, use the explicit-selection bulk review flow only: individually select the intended rows, choose the target disposition/reason, acknowledge human ownership, preview the exact one-time plan, and confirm it. There is no select-all or implicit filtered-view scope.
10. Optionally upload an Activity and/or Resource reference CSV. For each supplied reference, an optional revision/label may be entered exactly as known. The app records role, filename, revision/label, file size, and SHA-256 as evidence but does not establish reference authority.
11. Current browser reference checks are exact-code/unit checks and report `MATCH`, `UNIT_MISMATCH`, `NO_MATCH`, or `NOT_CHECKED`. Review them with the separate reference view: Exceptions by default, status/type filters, metadata-aware search, deterministic sorting, and optional grouping. Findings-view and reference-view settings preserve each other.
12. A separate pure operational-reference module can compare explicitly supplied Crew Code / Production Rate values as evidence only, but that capability is not yet exposed through the normal browser reference workflow. It must not be interpreted as an available automatic crew/productivity workflow until the governed UI/package contract is added.
13. Download individual findings/review/reference CSVs and the printable management summary, or download the deterministic ZIP review package. Exports are full-session snapshots regardless of the current presentation filters. Review-package v1 intentionally excludes original estimate/reference file bytes.
14. The review package includes `integrity.json`, which records byte size and SHA-256 for every other member. Verification also runs semantic snapshot consistency checks after integrity succeeds.
15. To inspect a previously exported ZIP without creating a review session, choose **Verify review package ZIP**. Verification and bounded preview are read-only and do not restore source estimate/reference bytes, mappings, approvals, or a live audit session.
16. To continue only the archived human-review work, choose **Archived review continuation**, select the package again, and explicitly acknowledge the snapshot-only boundary. The app re-verifies the package and creates a temporary `archived_review_snapshot` containing archived findings, dispositions, and recorded reference evidence only. Filters, sorting/grouping, single/bulk human dispositions, and review re-export remain available.
17. Archived continuation is **not** estimate restoration or re-audit. It cannot remap the estimate, rerun deterministic rules, replace/rerun governed references, prove that current project files still match the archived source, or establish approval/readiness/import validity. Re-exported archived packages preserve source-package provenance and explicit no-re-audit/no-source-bytes flags.
18. To compare two review cycles, use **Review Delta**. Upload an Earlier and Later review-package ZIP. Both are independently verified, then deterministic finding-evidence drift is reported separately from human review-state changes; governed reference-check and reference-metadata drift are compared separately. The comparison is descriptive only and does not infer improvement, correctness, or readiness.
19. For a true current estimate re-audit, upload the original/current estimate file again through the normal source-backed audit flow and supply any required governed reference files again. This creates a new audit; review-package v1 cannot restore the original source bytes.
20. Close the application when finished. Current source-backed audit state and archived continuation state exist only in temporary process memory and expire with the local session/process. Export a review package before closing if the review snapshot must be carried forward.

Unsupported / deliberately not claimed: encrypted/password-protected files, legacy `.xls`, images/PDFs, macros, formula evaluation, arbitrary advanced Excel features, automatic estimate correction, true source-file/session restoration from review-package v1, direct HeavyBid database/API access, production HeavyBid import validation, or production import automation.
